# Pull requests

Status: **In review**

## Loading a pull request

The reviewer either:

- presses **Open pull request** in the page and enters a link (`https://github.com/OWNER/REPO/pull/N`), `OWNER/REPO#N` or `OWNER/REPO N`, then **Ask Claude to load it**, or
- tells Claude in the chat which pull request to review.

Claude runs `tools/pr_loader.py`, which collects, for every markdown file the pull request adds or changes (`.md`, `.markdown`, `.mdx`; removed files are skipped):

- the file's content at the pull request's head commit,
- the lines the pull request added, and the line ranges its diff covers,
- the review comments on the file.

Claude writes these into the page's database. The page shows the first file and updates while it is open. If GitHub sends no diff for a file (very large changes), the file loads without change markers.

## Several files

When the pull request has more than one markdown file, a file picker under the title lists each file with its number of changed lines and comments, and "(new)" for added files. The page remembers the chosen file per pull request. "next file" and "previous file" switch by voice. Switching files starts the new file from its first section.

## Changed sections

- A section counts as **changed** when any of its lines was added or modified by the pull request. A new file counts as changed throughout and shows a "New file" banner instead of markers.
- Changed sections have a green line beside their line numbers.
- With **Say "changed"** on (the default), the reader says "Changed." before the first section of each run of changed sections.
- With **Changed only** on, reading and next/previous skip unchanged sections. Headings of chapters that contain changes are still read, for context. Skipped sections are dimmed.
- The header shows how many sections changed; the outline marks chapters with changes.
- "next change" and "previous change" jump to the start of the next or previous run of changed sections.

These settings appear only when the file has changes.

## Existing review comments

- Each review comment is shown under the section that contains its line, with the author, the comment and a link to it on GitHub.
- A comment whose line no longer exists in the current version (outdated) is placed by its original line and labelled **outdated**.
- With **Read comments** on (the default), the reader reads each comment after its section: "Comment from AUTHOR. …", or "Earlier comment from …" when outdated. The comment being read is highlighted.
- Comments from bots are shown, labelled "bot · not read aloud", and never read.
- A "Generated by Claude Code" footer at the end of a comment is not shown or read.
- The header and outline count comments, excluding bots.
- "next comment" jumps to the next section with a comment.

## Freshness

The page shows the pull request as it was when loaded. Loading it again refreshes it. When posting, Claude checks whether the pull request has new commits since it was loaded (see [posting-reviews.md](posting-reviews.md#safety)).
